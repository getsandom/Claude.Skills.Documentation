# Rules: improvements

- **Identifier:** `IMP_NNN`
- **Template:** [template.md](template.md)
- **File name:** `IMP_NNN-short-title.md` (e.g. `IMP_001-macros-in-body.md`)
- **Index description:** what the improvement delivers and its status
- **On closing:** remove the file and move the line to the Closed section of the index, with the outcome Implemented or Discarded
- **Subtopics:** none

## What to record

An improvement is a proposal for a feature or evolution outside the current scope,
worth recording so that it is not lost. Needs the system must meet are
requirements; choices already made are decisions.

## Lifecycle

- Edit the proposal as it matures, updating the status (Proposed, Approved,
  In implementation).
- When it is implemented, the behavior is described in the architecture (and in the
  decisions, if it involved choices) and the file is removed.
- When it is discarded, the file is also removed.
- In both cases, move its line to the Closed section of the index and record it in
  the history with the reason.
