# Rules: history

- **Identifier:** none
- **Template:** [template.md](template.md)
- **File name:** `YYYY-MM-DD.md`, one per day with changes (e.g. `2026-10-26.md`)
- **Index description:** the main actions of the day
- **On closing:** not applicable; history files are not removed
- **Subtopics:** none

## What to record

Content changes: creations, changes and removals of documents, such as a revised
decision, a resolved issue or a discarded improvement. Typo and formatting fixes and
index updates do not need to be recorded.

## Lifecycle

- The name uses year-month-day so that the files stay in chronological order;
  inside the file, dates also follow `YYYY-MM-DD`.
- Entries in chronological order, oldest first.
- Entries may be corrected, and their links updated when a document is renamed or
  moved, as long as they still describe what happened.
- For removed documents, the path stays as text between backticks, without a link.
- The history is not version control: git exists for that.
